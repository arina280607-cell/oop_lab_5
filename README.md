# Лабораторная работа № 5 — дерево поиска и умные указатели

Вариант 2: сотрудник — имя, отдел, зарплата. Ключ дерева — зарплата.

## Сборка в VS Code / Bash UCRT64

Откройте именно папку `lab_05`. Команды выполняются из неё в терминале
**UCRT64**, а не PowerShell. На проверенном компьютере GCC, CMake, Ninja
и установленный Google Test находятся в `C:/msys64/ucrt64`.

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug -DCMAKE_COMPILE_WARNING_AS_ERROR=ON
cmake --build build
ctest --test-dir build --output-on-failure
./build/lab_05.exe
```

Если CMake не находит установленный Google Test, добавьте при конфигурации
`-DCMAKE_PREFIX_PATH=C:/msys64/ucrt64`.
Если выбран другой компилятор, используйте отдельную папку сборки, например `build-ucrt64`,
и добавьте `-DCMAKE_CXX_COMPILER=C:/msys64/ucrt64/bin/g++.exe`.

Цели CMake: `lab05_core` — классы, `lab_05` — демонстрация,
`lab_05_tests` — тесты. Для GCC/Clang включены `-Wall -Wextra -Wpedantic`.
`CMAKE_COMPILE_WARNING_AS_ERROR=ON` превращает предупреждения в ошибки.
Google Test подключается как установленная библиотека; CMake его автоматически не скачивает.

## Контракт и владение

| Тип | Данные и ответственность | Копирование / перемещение |
|---|---|---|
| `Employee` | Имя и отдел `std::string`, зарплата `int`, общий счётчик объектов | Оба разрешены; каждый конструктор увеличивает счётчик, деструктор уменьшает, присваивание не меняет |
| `EmployeeTree::Node` | `shared_ptr<Employee> data`, `unique_ptr<Node> left/right` | Узлы передаются через их владеющие `unique_ptr`, а не копируются |
| `EmployeeTree` | `unique_ptr<Node> root_`, количество записей | Копирование запрещено; перемещение передаёт корень и оставляет источник пустым |
| `Criterion` | Абстрактная проверка `matches(const Employee&) const`, виртуальный деструктор | База используется по ссылке; конкретным критериям достаточно автоматически создаваемых операций |
| `Selection` | `unique_ptr<weak_ptr<const Employee>[]>`, размер, вместимость | Копирование создаёт свой массив наблюдателей; перемещение передаёт массив и обнуляет источник |

```text
EmployeeTree --unique_ptr--> Node
                             |--unique_ptr--> левый Node
                             |--unique_ptr--> правый Node
                             |--shared_ptr--> Employee
                                                ^
Selection --unique_ptr--> [weak_ptr, weak_ptr, ...]
```

### Данные сотрудника и ключ

- Зарплата — целое неотрицательное число рублей. Отрицательное значение вызывает
  `std::invalid_argument` до увеличения счётчика. Ноль допустим.
- Имя и отдел хранятся без нормализации. Допустимы пустые строки: они нужны
  для эталона `Employee{"", "", salary}`. Конструктор не отличает эталон от обычной записи.
- Отдел сравнивается точно, с учётом регистра: `IT` и `it` различаются.
- `<` и `==` сравнивают только зарплату. Поэтому сотрудники с одинаковой зарплатой
  являются дубликатами ключа даже при разных именах. Вставка второго отклоняется.
- Копирующий конструктор нужен для создания отдельной записи внутри узла.
  Перемещающий определён явно для корректного счётчика при создании перемещением.
  Присваивания `= default` корректны: строки управляют своей памятью, статический
  счётчик не присваивается как поле отдельного объекта.

### Узел, дерево и время жизни

`Node` полностью определён в `employee_tree.cpp`; заголовок содержит только
закрытое предварительное объявление. Конструктор, деструктор и перемещения дерева
определены после полного описания узла. Там компилятору известно, что уничтожает
`unique_ptr<Node>`. Копирование явно запрещено через `= delete` — это запрет
операции, а не ручное освобождение памяти.

Дерево владеет корнем; родитель владеет детьми. Запись хранится в `shared_ptr`,
поскольку `weak_ptr` должен наблюдать за объектом, управляемым совместным владением.
Непосредственно наблюдать через `weak_ptr` за объектом `unique_ptr` нельзя.
В обычном состоянии единственный владелец записи — её узел.

Поиск и выборка возвращают `weak_ptr<const Employee>`: результат не удерживает
запись и не позволяет изменить её ключ через полученный доступ. Вызов `lock()`
даёт временный `shared_ptr<const Employee>`. Пока он существует, запись живёт
даже после удаления из дерева. Поэтому тесты истечения не держат лишних владельцев.
`const` здесь защищает сотрудника, а не только сам объект указателя.

Вставка копирует сотрудника в новый узел. Изменение исходного локального сотрудника
не затрагивает запись дерева. При перемещении дерева узлы остаются на месте,
переходит владение корнем; размер источника обнуляется через `std::exchange`.
Перемещающее присваивание также освобождает прежнее дерево получателя.

Удаление возвращает `false` для отсутствующего ключа. Лист освобождается,
единственный ребёнок занимает место узла через передачу владения. Для двух детей
в узел переносится **указатель на запись преемника**, а не поля сотрудника:
крайний левый узел правого поддерева вырезается с сохранением его правого ребёнка.
Поэтому наблюдение за преемником остаётся живым, а за удалённой записью истекает,
когда исчезнут все временные владельцы.

### Критерий и общий обход

`DepartmentCriterion` хранит строку отдела; `AllCriterion` принимает любую запись.
База не знает о дереве и полях конкретного варианта. Метод дерева `select`
принимает `const Criterion&`, не копирует критерий и вызывает виртуальную проверку.

Один симметричный обход: левое поддерево, проверка текущей записи, правое поддерево.
Подходящая запись сразу добавляется в выборку; предварительного подсчёта и сортировки нет.
Время обхода O(n), стек рекурсии O(h), память выборки O(k), где k — число результатов.
Поиск, вставка и удаление занимают O(h); дерево не балансируется, в худшем случае h = n.
Высота пустого дерева 0, листа 1. Вычисление высоты и печать обходов занимают O(n).

### Собственный массив выборки

Вместимость растёт как 0, 1, 2, 4, 8 и далее. При росте создаётся новый массив
пустых `weak_ptr`, затем в него копируются добавленные наблюдения. Добавление
амортизированно O(1); отдельное расширение занимает O(k). Переполнение размера
при удвоении проверяется до выделения памяти.

`size()` считает ссылки, включая истёкшие; `capacity()` — выделенные места.
`empty()` означает нулевой размер. `at(i)` возвращает наблюдателя по значению
и бросает `std::out_of_range` при `i >= size()`.

Копия имеет свой массив, но наблюдает за теми же сотрудниками. Копирующее
присваивание использует copy-and-swap: сначала успешное создание копии, затем обмен.
Перемещение оставляет источник с нулевыми размером и вместимостью, готовым к повторному
использованию. Пустое дерево возвращает пустую выборку без выделения массива.

## Итоговая демонстрация

`main.cpp` вставляет шесть сотрудников, печатает обход и выбирает отдел `IT`:

```text
3
Dina IT 70000
Anna IT 80000
Vera IT 100000
```

Затем удаляется Анна с ключом 80000 — корень с двумя детьми. Печатается та же выборка:

```text
3
Dina IT 70000
[expired]
Vera IT 100000
```

Размер выборки остаётся 3. Перед чтением каждого элемента вызывается `lock()`.
После завершения блока дерева счётчик живых сотрудников должен быть 0.


Из терминала UCRT64 на Windows:

```bash

```

Скрипт использует ASan/LSan/UBSan, `-Werror` и останавливается при любой ошибке.
При первом запуске скачивает официальный архив Google Test в `build-memory`,
если его там ещё нет. Для имеющихся исходников можно задать `LAB05_GTEST_SOURCE` —
путь к каталогу `googletest`, содержащему `src/gtest-all.cc`.

### Как читать тест

`TEST_F(Lab05Test, ...)` объявляет отдельный сценарий. Фикстура `Lab05Test`
проверяет нулевой счётчик до и после каждого сценария. `EXPECT_EQ` сравнивает
ожидаемое и фактическое значения, `EXPECT_TRUE/FALSE` проверяет логический результат,
`EXPECT_THROW` — ожидаемое исключение. `ASSERT_TRUE` прекращает текущий тест,
если дальнейшие действия небезопасны, например если не удалось получить запись через `lock()`.

Например, `SelectionKeepsSizeWhenRecordExpires` создаёт дерево, отбирает отдел IT,
удаляет запись с зарплатой 80000 и проверяет одновременно прежний размер выборки,
истечение именно второй ссылки и сохранение двух остальных записей.
